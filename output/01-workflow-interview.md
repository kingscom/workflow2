# Task & Decision Map

인터뷰 정리일: 2026-11-01

현행화: 2026-11-01, Execution Design 중 사용자가 승인한 채널 관리·전체 저장·간단 요약·태그 Task 이동을 반영했다. 수행방식과 역할 결정은 [2단계 결과](02-execution-design.md)에서 관리한다.

상태: `✓ Confirmed`는 사용자 발언 또는 자료로 확인한 내용, `△ Draft`는 AI가 제안한 업무 구조·판단 가설, `? Need Check`는 다음 단계에서 확인할 내용이다. 확인된 운영 요구사항이 현재 구현되거나 기존 업무에서 이미 실행 중임을 의미하지는 않는다.

## 1. 업무 개요

- **업무명:** 교육 특강 주제 센싱
- **목적:** 담당자의 수작업 기술 탐색 부담을 줄이고 신뢰할 수 있는 기술 채널을 지속 수집·정리하여 특강 후보 주제를 발굴한다. `✓ Confirmed`
- **Trigger:** 매일 1회. 실행 시각·시간대는 미정이다. `✓ Confirmed / ? Need Check`
- **주요 Input:** 기업 기술 채널의 글, 채널별 마지막 정상 수집 기준, 기존 저장 이력, 최초 실행 시 사용자가 지정하는 시작 날짜. `✓ Confirmed`
- **최종 Output:** 모든 수집 글의 저장 기록과 간단 요약. 주제명, 해당 후보 기준과 근거, 예상 대상·난이도, 출처·게시일, 주의점은 참고 정보로 제공하며 후보 여부로 저장을 제한하지 않는다. `✓ Confirmed 전체 저장·요약 / △ 참고 표시 상세`
- **요약 형식:** 글마다 한국어 3문장 요약. 출처·태그·주의점은 별도로 제공하고 일일 묶음 요약은 우선 제외한다. `✓ Confirmed`
- **글 단위 복구:** 요약 실패 시 저장 자료를 유지한다. 다음 실행에서 해당 글만 재로딩하여 재분석하고, 다시 실패하면 실패 상태로 남겨 자동 반복을 중단한다. 근거 부족 태그는 '미확인'으로 표시하고 사용자 응답을 기다리지 않는다. 수동 재시도의 추가 허용 범위는 미정이다. `✓ Confirmed / ? Need Check`
- **주요 이해관계자:** 교육 담당자, 직무·기술 담당자, 별도 최종 주제 결정자. 역할 명칭은 초안이며 결정자의 구체적인 소속·권한은 미확인이다. `△ Draft`
- **업무 범위:** 후보 발굴·정리·저장까지이며 최종 특강 주제는 별도로 결정한다. 강사 섭외와 교육 운영은 이 Map에서 다루지 않는다. `✓ Confirmed / △ 범위 경계`
- **수집 우선순위:** 기업 기술 채널 우선. 다른 유형의 자료를 제외한다는 규칙은 확인되지 않았다. `✓ Confirmed / ? Need Check`
- **채널 관리:** 사용자가 채널을 제시하고 추가·수정·삭제한다. 삭제는 향후 수집 중단이며 기존 자료는 보존한다. 주소 수정 시 기존 기록도 보존한다. 새 주소의 기준·재등록 정책은 미정이다. `✓ Confirmed / ? Need Check`
- **기준 갱신:** 수집 자료가 안전하게 저장되면 채널 수집 기준을 갱신하고 요약 완료는 기다리지 않는다. 글 단위 복구는 저장 글 식별자로 별도 관리한다. `✓ Confirmed`
- **결과 저장 복구:** 생성된 요약 결과를 보존해 저장만 재시도하고 AI를 다시 호출하지 않는다. 재실패하면 저장 실패로 남긴다. 보존 구현·재시도 시각은 후속 설계 사항이다. `✓ Confirmed / ? Need Check`
- **후보 기준:** 최신 기술 동향, 구체적인 실무 적용법, 생산성 개선 사례 중 하나만 충족해도 후보에 포함할 수 있다. 기술 담당자에게 유용한 글을 폭넓게 저장하고 직무·난이도 태그를 부여한다. `✓ Confirmed`
- **수집 시작점:** 저장된 마지막 정상 수집 기준을 반드시 사용한다. 이력이 없으면 시작 날짜를 사용자에게 질문하며, 전날이나 최근 일정 기간으로 임의 설정하지 않는다. `✓ Confirmed`
- **실패 처리:** 채널별로 기준을 유지한다. 실패한 채널은 기준을 갱신하지 않고 다음 실행에 재수집한다. `✓ Confirmed`
- **참고 사례:** [컬리의 AI 병렬 오케스트레이션 실전 운용기](https://helloworld.kurly.com/blog/ai-orchestration-2). 사용자가 제시한 예시이며 전체 채널 목록이 확정된 것은 아니다. 글의 생산성 성과는 저자의 사례 보고이지 일반적으로 검증된 효과가 아니다.

## 2. Workflow

수집 채널 추가·수정·삭제
→ 저장된 수집 기준 확인
→ 이력이 없으면 시작 날짜 질문
→ 신규 글 수집
→ 저장 이력과 중복 확인
→ 모든 수집 글 보존 및 간단 요약·대상/난이도 태그 작성
→ 요약·참고용 후보 근거 저장
→ 정상 완료한 채널의 수집 기준 갱신

Task 분해와 순서는 `△ Draft`이며 수집 주기·시작점·실패 처리·후보 기준·출력 항목은 `✓ Confirmed`이다. 수집 또는 저장에 실패한 경우의 정상 완료 판정 상세는 다음 단계에서 정의한다.

## 4. 핵심 암묵지

### Tacit Knowledge 1: 기술 정보의 교육적 가치

- **상황:** 세 기준 중 하나에 해당하는 글을 특강 후보로 검토한다.
- **경험적 Cue:** △ 구체적인 문제, 해결 과정, 적용 조건이 설명되어 있다.
- **판단:** △ 대상자가 배울 내용을 특강 주제로 재구성할 수 있는지 판단한다.
- **예외:** △ 특정 조직·도구·환경의 성공 사례를 일반화하기 어려운 경우.
- **상태:** `△ Draft`. 실제 담당자의 경험 기준으로 확인된 것은 아니다.

### Tacit Knowledge 2: 대상·난이도 분류

- **상황:** 유용한 기술 글을 폭넓게 저장하며 직무·난이도 태그를 부여한다.
- **경험적 Cue:** △ 선수지식, 기술 용어, 사례의 전문성, 적용 업무.
- **판단:** △ 예상 대상 직무와 난이도를 추정한다.
- **예외:** △ 여러 직무에 해당하거나 수준 판단에 충분한 정보가 없는 글.
- **상태:** 태그 방식은 `✓ Confirmed`, 경험적 분류 기준은 `? Need Check`.

## 5. 핵심 Decision

### Decision 1: 수집 시작점 결정

- **Goal:** 임의 범위 설정과 수집 누락을 방지한다.
- **Evidence:** 채널별 저장된 마지막 정상 수집 기준의 유무.
- **Criteria:** 저장 기준이 있으면 사용하고, 없으면 시작 날짜를 질문한다. `✓ Confirmed`
- **Inference:** 저장 이력 유무에 따른 조건 적용. 추론 유형은 △ 연역적 조건 판단으로 볼 수 있다.
- **Decision:** 저장 기준 사용 / 사용자 시작 날짜 확인. 자동으로 전날을 선택하지 않는다.
- **Risk/Uncertainty:** 날짜 경계·시간대·손상된 기준 처리·늦게 게시된 글 처리 미정.

### Decision 2: 요약·참고용 후보 분류

- **Goal:** 직무·기술 담당자에게 유용한 특강 후보를 확보한다.
- **Evidence:** 원문에 나타난 최신 동향, 실무 적용법, 생산성 개선 사례.
- **Criteria:** 세 기준 중 하나 이상에 해당하면 포함 가능하며 직무·난이도로 사전 제한하지 않고 태그를 부여한다. `✓ Confirmed`
- **Inference:** △ 근거와 기준의 대조, 외부 사례와 대상자의 업무를 비교하는 유추. 실제 사고 방식은 미확인이다.
- **Decision:** 모든 글을 저장하고 간단 요약을 제공한다. 후보 해당 여부는 참고 표시이며 저장 포함·제외나 사전 승인으로 쓰지 않는다. 최종 특강 주제 결정과 구분한다. `✓ Confirmed 저장·요약 / △ 후보 표시`
- **Risk/Uncertainty:** 기술적 유용성 판단 편차, 홍보성 주장, 성과 과장, 단일 사례의 일반화, 기준별 최소 근거 수준 미정.

### Decision 3: 채널별 수집 기준 갱신

- **Goal:** 실패 구간을 보존하여 다음 실행에서 이어서 수집한다.
- **Evidence:** 채널별 수집 결과와 저장 결과.
- **Criteria:** 수집 자료가 안전하게 저장된 채널만 기준을 갱신한다. 요약 완료는 기다리지 않으며 채널 수집·자료 저장 실패는 기존 기준을 유지한다. `✓ Confirmed`
- **Inference:** △ 완료 조건을 적용하여 갱신 가능 여부를 판단한다.
- **Decision:** 기준 갱신 / 기준 유지 후 다음 실행에 재수집.
- **Risk/Uncertainty:** 안전한 저장의 검증·부분 저장·갱신 기준값과 저장 일관성 구현은 미정. 요약 성공과 기준 갱신은 분리한다.

## 6. 확인이 필요한 사항

1. 실제 수집 채널 목록과 신뢰성 기준, 기업 기술 채널 외 자료의 포함 범위.
2. 실행 시각·시간대, 저장 기준값의 의미, 날짜 경계·늦게 게시된 글·수정 글·중복·실패 및 정상 완료의 판정 기준.
3. 저장 위치·원문 보존 범위, 직무·난이도 태그 정의、재로딩 성공 판정·수동 재시도 범위。글별 3문장과 1회 자동 재시도 후 실패 유지 정책은 확인됐다.

위 항목은 `? Need Check`로 남긴다. 인터뷰를 추가로 이어가기 위한 질문 목록이 아니라 다음 Work Execution Design에 영향을 주는 미확인 사항이다.
