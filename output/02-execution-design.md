# Execution Design

업무: 교육 특강 주제 센싱

정리일: 2026-11-01

현재 단계의 `✓ Confirmed`는 사용자 합의, `△ Proposed`는 AI 추천, `? Need Check`는 미확인 사항이다. 업무 기준은 1단계 파일에서 관리한다. 이 문서는 설계 결과이며 구현 완료를 의미하지 않는다.

## 1. Input Reference & Changes

- **업무 기준:** [1단계 Workflow Interview](01-workflow-interview.md)의 업무 개요, T1~T6, 핵심 Decision과 미확인 사항을 필요한 경우 참조한다. 전체 본문을 복사하지 않는다.
- **변경 이력 (2026-11-01):** 사용자 교정에 따라 T1 채널 관리, T5 전체 저장 대상의 간단 요약·참고 분류, T6 자료·요약 저장으로 1단계의 관련 항목을 현행화했다. 상세 근거는 1단계 변경 이력에 있다.
- **영향 검토:** ABCD 확인 답변에 따라 T5 AI 자동 요약·태그 권한을 Confirmed로 갱신하고 T3 대상 글 재로딩, T6 실패 상태 저장 역할을 연결했다. 상세 ABCD는 [3단계 결과](03-abcd-design.md)를 참조한다. 다른 Task의 미합의 Mode는 유지한다.
- **후속 참조:** 3단계 이후는 필요한 업무 근거만 1단계에서, 역할 근거만 이 파일에서 읽는다. 앞 단계가 바뀌면 영향받는 결정도 재검토하고 미검토 항목은 Need Check로 표시한다.

## Current Stage — Execution Design

### 최신 답변 반영

- `✓ Confirmed`: 사용자가 수집 채널을 제시하며 추가·수정·삭제할 수 있어야 한다. AI가 임의로 채널을 추가하지 않는다.
- `✓ Confirmed`: 모두 저장하고 간단하게 요약한다. 근거 부족이나 후보 적합성 판단을 저장 전 승인 조건으로 사용하지 않는다.
- `✓ Confirmed`: 대상·난이도 태그 추정은 T5로 옮기고 T6는 System의 저장·기준 갱신으로 분리한다.
- `△ Proposed`: '모두'는 사용자가 지정한 채널과 수집 범위에서 확보한 모든 글로 해석한다. 동일 글의 중복 사본을 계속 추가한다는 뜻은 아니다.
- 이전 초안의 T5 후보 포함·제외는 저장 여부 결정이 아닌 참고용 후보 표시로 바꾼다. 저장 전 예외 검토 대기 제안은 철회한다.

## 2. Execution Design Summary

사용자가 채널을 관리하고 System이 수집·보존하며 AI가 글별 한국어 3문장 요약과 태그를 사전 승인 없이 생성한다. T5의 AI / Agent Mode와 T6의 System 저장·기준 갱신 분리는 사용자가 승인했다. 요약 실패 시 System이 다음 실행에 해당 글만 재로딩하고 AI가 재분석하며, 다시 실패하면 실패 상태로 유지한다. 근거 부족 태그는 미확인으로 표시하며 저장이나 처리를 Human 응답 대기로 막지 않는다. 최종 특강 주제 결정은 별도로 유지한다.

### 수정된 Workflow

사용자의 채널 추가·수정·삭제
→ System이 채널별 저장 기준 확인, 없으면 시작 날짜 질문
→ 매일 신규 글 수집
→ 동일 글 식별 및 모든 수집 자료 저장
→ AI가 간단 요약·참고용 후보 근거·대상/난이도 생성
→ System이 분석 결과 저장

자료가 안전하게 저장되면 채널 기준을 갱신하고 요약은 기다리지 않는다。요약 실패의 1회 글 단위 복구와 결과 저장 실패의 재저장을 분리한다。재저장은 AI를 호출하지 않고 재실패 시 저장 실패를 유지한다。이 정책은 `✓ Confirmed`며 안전한 저장 검증·재시도 시각·재로딩 성공 판정은 후속 설계 사항이다.

## 4. HITL Map

모든 글을 저장하므로 후보별 Approval HITL은 두지 않는다. 아래 개입은 `△ Proposed`이며 저장 전 승인 절차가 아니다. AI와 무관한 채널 등록·최초 날짜 입력·System 장애 복구는 일반 Human/System 업무로 구분한다.

| Task | HITL Type | Trigger | Human Role | Human Decision | Return Path |
|---|---|---|---|---|---|
| T5 | Knowledge HITL, 사후 선택적 교정 | 태그 기준 미정 또는 담당자가 요약 오류 발견 | 교육 담당자·필요 시 기술 전문가 | 요약/태그 수정 또는 기준 보완 | 저장 글은 유지하고 보완 기준으로 재분석 |

근거 부족 태그는 미확인으로 표시하고 사람 응답을 기다리지 않는다. 요약 실패 시 자료 유지, 대상 글만 재로딩·재분석 1회, 재실패 시 실패 유지가 Confirmed다. 모든 오류의 강제 알림은 미합의이며 선택적 사후 교정은 자동 실행의 전제조건이 아니다.

## 5. AI / Agent Candidates

### Candidate 1: T5 간단 요약·참고 분류

- **Task:** 저장된 글의 짧은 요약, 후보 기준 근거, 예상 대상·난이도 태그 작성.
- **추천 Mode:** AI / Agent. 사전 승인 없는 요약·태그 생성에 한정. `✓ Confirmed`
- **Awareness 후보:** 새로 저장되었거나 분석 미완료인 글, 원문 확보 상태, 기존 요약 유무.
- **필요한 Knowledge:** 원문·출처·게시일, 세 후보 기준, 직무·난이도 태그 정의. 태그 정의는 미확인.
- **주요 Inference:** 핵심 내용 추출·압축, 원문 근거와 후보 기준 대조, 직무/선수지식 기반 분류.
- **Decision:** 요약 내용·참고용 분류·불확실성 표시. 수집 자료 저장 여부와 최종 주제는 결정하지 않는다.
- **예상 Action:** 분석 결과를 System에 전달. 채널·수집 기준·기존 원문을 변경하지 않는다.
- **Human Boundary:** 채널 변경과 최종 특강 선정은 사용자, 요약/태그 교정은 담당자.
- **Risk:** 환각·성과 일반화·태그 오류·원문의 지시를 업무 지시로 오인.
- **Validation:** 원문과 요약의 일치, 출처 존재, 주장과 근거 구분, 실패 시 원문 유지. 원문은 자료로만 취급하며 실행 지시로 따르지 않도록 제한하는 것을 제안한다.
- **상태:** 전체 저장·글별 3문장·AI Mode·사전 승인 없는 요약/태그 생성·글 단위 1회 복구는 `✓ Confirmed`; 태그 정의 및 검증 상세는 `? Need Check / △ Proposed`.

## 6. Human / System / No Change 영역

### Human 중심

수집 채널 제시·추가·수정·삭제는 사용자 권한이다. 최초 이력이 없는 채널의 시작 날짜도 사용자가 지정한다. 최종 특강 주제는 별도로 결정하며 이 단계에서 AI에 위임하지 않는다. 담당자의 구체적인 소속·검토 책임은 미확인이다.

### Rule / System

T2 범위 확인, T3 수집, T4 동일 글 식별, T6 저장·갱신을 담당하도록 제안한다. T1 변경 요청 반영도 정형적인 System 기능으로 제안한다. 매일 수집 주기와 채널별 실패 기준 유지 정책은 보존한다. AI 분석 결과와 수집 자료 저장을 분리하여 요약 실패가 원문 누락을 만들지 않도록 한다.

### No Change

최종 특강 주제를 별도로 결정하는 경계는 유지한다. T1 채널 선택을 사용자에게 남기고 매번 AI 평가를 강제하지 않는다. T2~T6의 현행 처리량·소요 시간 정보는 부족하므로 효과를 수치로 주장하지 않으며, 저빈도 예외는 불필요한 Agent 대신 기존 수동 복구를 대안으로 남긴다.

## 7. 주요 설계 판단

### Decision 1: 저장 전 HITL 대신 전체 저장

사용자의 교정에 따라 AI의 후보 판단을 저장 게이트로 쓰지 않는다. 정보 보존과 이후 사람의 선택을 우선한다. 근거 부족 자료도 요약의 주의점으로 구분하는 것을 제안하며 승인 대기로 숨기지 않는다. 대안인 모든 후보 사전 승인은 사용자의 전체 저장 요구와 맞지 않아 채택하지 않는다.

### Decision 2: 비정형 요약과 결정론적 저장 분리

AI는 본문 요약·태그에, System은 수집·기록·기준 갱신에 배치한다. 모든 글에 사람이 요약을 쓰는 Human + AI Assist는 저빈도 운영 시 대안이나 매일 반복 부담을 줄이는 목표에는 AI 생성이 더 적합해 보인다. 단순 키워드 Rule은 대안이지만 실무 맥락 요약에 한계가 있어 보조 수단으로 제안한다.

### Decision 3: 자동 채널 확장·유사 글 삭제 비추천

사용자가 채널을 제시하고 관리하므로 AI의 자율 채널 추가는 허용하지 않는다. 모든 글을 남기는 목적상 의미적으로 비슷하다는 이유만으로 AI가 자료를 삭제하거나 제외하지 않는다. 동일 글 재수집 시 처리 방식은 별도 기준으로 정의한다.

### Decision 4: 수집 완료와 AI 분석 완료 분리

AI 요약 실패는 System의 대상 글 재로딩과 AI의 재분석으로 1회 복구한다. 재실패하면 Failed로 유지하고 자동 반복하지 않는다. 채널 수집·자료 저장 실패는 기준 유지로 별도 처리한다. 자료가 안전하게 저장되면 요약을 기다리지 않고 기준을 갱신한다. 결과 저장 실패는 생성 결과만 재저장하며 AI 호출 없이 재실패 상태를 유지한다. 원문 보존 범위·저장 검증 구현은 미확인이다.

## 8. 확인 필요사항

1. 사용자 제공 채널 목록, 새 주소의 기준·재등록 정책, 최초 시작일, 실행 시각·시간대.
2. 저장 위치·형식·원문 보존 범위, 동일 글·수정 글 처리, 안전한 저장 검증·기준값 경계, 실패 결과 보존 방식·재저장 시각.
3. 태그 정의, 재로딩 성공 판정·수동 추가 재시도 허용 범위、선택적 사후 교정 기능 상세. 글별 3문장·AI 권한·1회 자동 복구는 합의됐다.

채널 삭제는 향후 수집 중단이고 기존 자료는 보존한다。주소 수정 시 기존 기록도 보존하며 새 주소 기준은 미정이다。`✓ Confirmed` 정책이며 상세 Architecture, API, DB Schema는 다음 단계에서 설계한다.

## 9. Next Stage Handoff

### Confirmed Task Set

사용자 채널 관리(추가·수정·삭제), 매일 1회 수집, 저장 기준 우선/없으면 시작일 질문, 실패 채널 기준 유지, 전체 자료 저장과 간단 요약, T5 태그 추정/T6 System 저장 분리를 반영한다. T1~T6 ID는 이전 단계와 연결하되 T1은 채널 관리, T5는 간단 요약·참고 분류, T6는 저장·갱신으로 현재 정의를 사용한다.

### Role Allocation

Human: T1 채널 선택과 변경 요청, 최초 시작일, 별도 최종 주제 결정.
Rule / System: T2~T4 추천, T6 합의된 역할 분리, T1 변경 반영 추천.
AI / Agent: T5 사전 승인 없는 요약·태그 생성은 Confirmed. 해당 글 재로딩은 System에, 재분석은 AI에 두며 재실패 후 자동 반복을 중단한다.

### Agent Candidates

T5만 상세 ABCD 후보로 제안한다. 채널 관리·수집·저장·기준 갱신까지 포괄하는 자율 Agent는 추천하지 않는다.

### HITL Points

후보 저장 전 Approval 없음. 선택적 사후 Knowledge 교정만 제안하며 검토 대기 없이 자료를 보존한다. System 장애 복구는 별도 운영 예외로 관리한다.

### Human-only Decisions

채널 추가·수정·삭제 요청, 이력 없는 채널의 시작일, 최종 특강 주제 선정. 신뢰성 기준과 조직별 책임자는 추후 정의한다.

### Rule/System Tasks

채널 변경 반영, 저장 기준 조회, 범위 수집, 동일 글 식별, 자료/분석 결과 저장, 안전한 채널 기준 갱신. AI는 수집 기준이나 채널 목록을 임의 변경할 수 없다.

### No Change Tasks

별도 최종 주제 결정 경계 유지. 그 외 현재 방식 유지 효과는 정보 부족으로 미확정이다.

### Constraints / Risks

모두 저장하되 의미 기반 제외를 하지 않는다. 채널 삭제는 향후 수집 중단이고 기존 기록은 보존한다. 자료 저장 후 기준을 갱신하며 요약 완료를 기다리지 않는다. 결과 저장 실패는 생성 결과만 재저장하며 AI 호출 없이 재실패 상태를 유지한다. 원문 보존 범위·날짜 경계·실패 결과 보존 구현은 Need Check다. 요약·태그는 참고 정보이며 외부 연동은 실행하지 않았다.

### 변경 이력

- 2026-11-01 Workflow 확인: 사용자 1·2·3번 동의로 T6의 자료 저장 후 기준 갱신과 AI 재호출 없는 결과 저장 복구를 확정했다. T1 삭제·주소 수정의 기록 보존 정책도 반영했다. 다른 미합의 Mode는 유지한다.
- 2026-11-01 ABCD 확인: 사용자 동의로 T5 AI Mode·글별 3문장 요약을 확정했다. 해당 글 재로딩 및 재실패 유지 요청에 따라 T3/T5/T6 복구 연결을 갱신하고 이전의 무제한 미완료 재분석 해석을 폐기했다. 업무 기준은 1단계, 상세 State·검증 초안은 3단계에서 관리한다.
