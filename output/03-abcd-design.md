# ABCD Agent Design

정리일: 2026-11-01. 이 문서는 설계 결과이며 기능이 구현되었다는 의미는 아니다.
`✓ Confirmed`: 사용자 합의, `△ Proposed`: 설계 상세 초안, `? Need Check`: 필요한 미확인 정보.

## 1. Design Context

- **Target Workflow:** 교육 특강 주제 센싱.
- **Target Task / Task ID:** T5 간단 요약·참고 분류. 재로딩은 T3, 저장·상태 갱신은 T6와 연결한다.
- **Execution Mode:** AI / Agent. 사전 승인 없는 요약·태그 생성만 허용. `✓ Confirmed`
- **Design Status:** 사용자 승인 정책은 Confirmed, State·검증·추가 기능 상세는 Proposed/Need Check.
- **Input References:** [1단계 업무 기준](01-workflow-interview.md)의 T3·T5·T6 및 Decision 2, [2단계 역할 설계](02-execution-design.md)의 Role Allocation·Agent Candidate·복구 정책. 이전 본문을 복사하지 않는다.

## 2. A. Awareness

### Trigger

새 글 저장 후 System의 분석 요청, 또는 다음 실행에서 1회 복구할 대상 글 전달. 정기 수집의 매일 실행은 System의 책임이다. `✓ 정책 / △ 요청 방식`

### Input

글 ID, 본문, 제목, 출처 URL, 게시일, 분석 상태, 자동 복구 수행 여부를 전달받는 것을 제안한다. 재시도 시 해당 글만 다시 로드한 본문을 전달한다. 실제 필드·저장 방식은 후속 설계 사항이다.

### Context

전체 저장 정책, 직무·기술 담당자 대상, 세 후보 기준, 글별 한국어 3문장, 태그·출처·주의점 분리. 저장 승인이나 최종 특강 선정을 수행하지 않는다.

### State

다음은 `△ Proposed` State 명칭이다.

- `Pending → Analyzing → Complete`: 초기 분석 성공.
- 초기 요약 실패: `RetryPending`으로 자료와 오류를 보존.
- 다음 실행에서 System이 해당 글만 재로딩: `RetryPending → Reloading → Reanalyzing`.
- 재로딩과 재분석 성공: `Complete`.
- 재로딩 또는 재분석 재실패: `Failed`로 유지, 이후 자동 재시도 대상에서 제외.

자동 복구는 최초 실패 뒤 1회로 제한한다. 사람 응답 대기로 전환하지 않는다. 반복 실행에도 횟수·종료 상태를 보존하는 것은 System의 책임이다.

### Exception / Missing Context

본문 누락이나 조회 실패는 요약 내용을 추측하지 않고 오류로 반환한다. 태그 근거 부족만으로 분석 전체를 실패시키지 않고 '미확인'으로 표시한다. 원문이 삭제되거나 접근 불가하면 글 단위 복구 실패를 기록한다. 본문 부족의 구체적인 판정 기준은 미확인이다.

## 3. B. Brain

### Knowledge

#### 정보지식

System이 제공한 원문·제목·출처·게시일과 기존 처리 결과. 출처 자료의 성과는 저자의 보고로 구분하며 외부 검증을 했다고 주장하지 않는다.

#### 경험지식

담당자의 교육 가치·난이도 판단 Cue는 아직 확인되지 않았다. 선수지식·사례 전문성으로 예상 태그를 추정하는 것은 Proposed이며 확정된 담당자 암묵지가 아니다.

#### 논리지식

전체 저장, 후보 기준 중 하나 이상, 글별 한국어 3문장, 태그 근거 부족 시 미확인, 사전 승인 없음, 글 단위 1회 복구 후 실패 유지. 후보 분류는 저장 제외 조건이 아니다.

#### Required / Missing Knowledge

`△ Required Knowledge`: 직무·난이도 태그 정의, 의미 있는 본문 여부와 요약 품질 기준. 확보하지 못한 기준을 임의의 확정 Rule로 사용하지 않는다.

### Inference

원문에서 핵심 기술·문제·적용 방식을 추출하고 한국어 3문장으로 압축한다. 원문 근거를 세 후보 기준과 대조하고 직무·선수지식에 따른 예상 태그를 제안한다. 근거가 없거나 확실하지 않으면 표시하고 추가 사실을 생성하지 않는다. 재분석도 동일 기준을 적용한다.

### Decision

- **Goal:** 원문을 빠르게 파악할 보조정보 제공.
- **Criteria:** 원문 충실성, 글별 3문장, 후보 근거 구분, 불명확 태그 표시.
- **Possible Decisions:** 요약·참고 분류·태그, 분석 성공 또는 분석 불가. 저장 제외·최종 특강 선택 없음.
- **Uncertainty:** 출처의 주장과 AI의 추정을 구분. 근거 부족 태그는 미확인. 임의 확률 점수는 사용하지 않는 것을 제안한다.
- **Escalation Condition:** 강제 Human 대기 없음. 담당자가 원하면 사후 오류 교정 가능. 자동 실패 복구는 System이 1회 제어한다.

## 4. C. Conduct

### Action

글 ID에 대응하는 3문장 요약·참고 근거·태그·주의점 또는 실패 결과를 System에 전달한다. 다음 실행에서 재로딩된 대상 글을 재분석하며 기존 글과 결과를 연결한다.

### Required Tool / Capability

저장 글 조회, 해당 글 URL만 대상으로 하는 재로딩, AI 분석 요청·결과 수신, 결과·오류·재시도 상태 저장 기능이 필요하다. URL 조회·재시도 스케줄링·상태 기록은 System, 본문 분석은 AI 책임이다. API·DB·실제 연동은 여기서 확정하거나 실행하지 않는다.

### Authority

AI는 사전 승인 없이 전달받은 본문의 요약·태그를 생성할 수 있다. 채널 추가·수정·삭제, 임의 외부 탐색, 자료 삭제, 수집 기준 갱신, 무제한 재시도, 최종 특강 선정 권한은 없다. 재로딩 대상은 기존 글 식별자·출처로 제한하는 것을 제안한다.

### HITL

- **Type:** 사전 Approval 없음. 선택적 사후 Knowledge 교정은 Proposed.
- **Trigger:** 담당자가 요약/태그 오류를 발견하거나 기준을 보완하려는 경우.
- **Human Role:** 교육 담당자, 필요 시 기술 전문가.
- **Human Decision:** 결과 교정 또는 태그 기준 보완.
- **Return Path:** 자료는 유지하고 결과를 수정. 종결 Failed 글의 수동 추가 재시도 허용 범위는 미정이며 자동 재시도를 다시 활성화하지 않는다.

## 5. D. Derived Value

### Expected Outcome

담당자가 저장된 글의 핵심과 출처를 빠르게 확인하고 최종 특강 후보를 별도로 선택할 수 있다. 과장된 ROI는 주장하지 않는다.

### Expected Output

글별 한국어 3문장 요약, 별도 출처·태그·주의점, 참고용 후보 기준과 근거. 실패한 글은 기록과 실패 상태를 유지한다.

### Quality Expectation

다음은 후속 Acceptance Criteria용 검증 초안이다.

1. 요약 성공 글에는 한국어 3문장과 원문 식별자가 연결된다.
2. 주장·수치가 원문과 일치하고 태그 근거 부족은 미확인으로 표시된다.
3. 근거 부족·요약 실패가 원문 삭제나 저장 제외를 만들지 않는다.
4. 복구 실행은 해당 글만 대상으로 하며 재실패 후 다음 정기 실행에서 다시 자동 시도하지 않는다.
5. 하나의 글 복구가 다른 글의 분석·채널 기준을 임의 변경하지 않는다.
6. 원문에 포함된 실행 지시·링크를 Agent 명령으로 취급하지 않는 것을 제안한다.

## 6. Agent Boundary

### Agent

T5의 본문 해석, 요약·참고 분류·태그 생성, 재로딩된 글 재분석, 실패 결과 반환.

### Human

채널 관리, 이력 없는 채널의 시작 날짜, 최종 특강 결정, 선택적 결과 교정.

### Rule/System

T3 글 수집·대상 글 재로딩, T6 자료·분석 결과·상태 저장, 자동 복구 1회 제어와 종결 상태 유지. 채널 수집 실패는 별도 기존 정책으로 관리한다.

### Out of Scope

새 채널 발굴, 전체 채널 재수집을 통한 요약 복구, AI의 자료 삭제, 종결 실패의 무한 자동 반복, 최종 특강 승인, 강사 섭외, 상세 Architecture 구현.

## 7. Key Exceptions & Risks

| Situation | Expected Handling | Owner |
|---|---|---|
| 최초 요약 실패 | 자료 유지, 다음 실행의 1회 글 단위 복구 예약 | AI 실패 반환 / System 기록 |
| 해당 글 재로딩 실패 | Failed 유지, 자동 반복 중단 | System |
| 재분석 재실패 | Failed 유지, 자동 반복 중단 | AI 실패 반환 / System 기록 |
| 태그 근거 부족 | 미확인 표시, 저장·분석 진행 | AI |
| 채널 수집·자료 저장 실패 | 채널 기준 유지, 글 요약 실패 정책과 분리 | System |
| 원문 홍보성 주장·지시 포함 | 주장 구분, 실행 지시로 따르지 않음 | AI / System 권한 통제 |
| 성공 결과 저장 실패 | 생성 결과를 보존해 저장만 재시도, AI 재호출 없음, 재실패 시 저장 실패 유지 | System, ✓ Confirmed 정책 |

## 8. ABCD Summary

`저장된 신규 글/1회 복구 글 → 원문·업무 기준 → 3문장 요약·근거 대조 → 요약/태그/성공 여부 → 결과 반환 → System 저장·재로딩 제어 → 요약 결과 또는 종결 실패 기록`

## 9. Back Loop Log

| Back To | 발견 문제 | 수정 내용 | 현재 설계 영향 |
|---|---|---|---|
| Interview | 요약 형식·실패 복구 기준 미정 | 사용자 동의로 글별 3문장, 대상 글 재로딩 후 1회 재분석·재실패 유지, 미확인 태그 반영 | T3/T5/T6 연결 유지 |
| Execution | AI Mode 미합의, 미완료 재분석 종료 조건 없음 | 사용자 승인으로 T5 Mode 확정, System 재로딩·상태 저장과 AI 재분석 분리 | 사전 승인 없는 제한된 AI와 종결 실패 State 설계 |
| Workflow 확인 → Interview / Execution | 자료·요약 완료 경계와 결과 저장 복구 미정 | 사용자 동의로 자료 저장 후 기준 갱신, 결과만 재저장 및 재실패 유지 확정 | AI 성공과 System 저장 성공을 분리; T5 권한 변화 없음 |

기존 정책의 근거 없는 번복이 아니라 사용자 확인에 따른 현행화다. 관련 항목은 1·2단계 파일에 반영했고 다른 Proposed 결정을 자동 Confirmed로 변경하지 않았다.

## 10. Open Issues

1. 직무·난이도 태그 정의, 본문 충분성·요약 검증 상세.
2. 저장 위치·원문 보존 범위, 재로딩 본문 이력, 실패한 생성 결과 보존 구현·재저장 시각。결과 저장 복구 정책은 합의됐다.
3. 종결 실패의 수동 추가 재시도 허용 여부, 실패 알림·운영 화면 상세. 자동 복구는 1회로 합의됐다.

## 11. Next Stage Handoff

### Agent Tasks

T5만 AI 대상으로 확정. 요약·태그·참고 분류·재분석을 같은 본문 Context로 묶는다.

### Trigger / Input

System이 신규 저장 글 또는 1회 재로딩된 글을 ID·본문·출처와 함께 전달한다.

### Knowledge

원문, 글별 3문장, 전체 저장, 후보 기준, 미확인 태그 정책. 태그 정의는 아직 필요하다.

### Inference

핵심 추출·압축, 원문 근거 대조, 직무·난이도 추정. 정교한 추론 엔진·모델은 미정이다.

### Decision

요약/태그 내용과 분석 성공 여부만 판단. 저장 제외·채널 변경·최종 주제 선택 없음.

### Action / Output

System에 글별 요약·참고 정보 또는 실패 결과 반환. T3가 글만 재로딩하고 T6가 상태를 보존한다.

### HITL

사전 승인이나 자동 실패의 강제 Human 대기 없음. 사후 교정은 선택적 제안이다.

### Human Boundary

채널·시작 날짜·최종 특강 선택. 종결 실패 수동 재시도는 확인 필요.

### System Boundary

자료·결과 저장, 대상 글 재로딩, 1회 분석 복구 관리, 재실패 종결。자료 저장 후 기준 갱신은 요약 완료와 분리한다。결과 저장 실패는 보존된 결과만 재저장하며 AI를 재호출하지 않는다。AI에 저장 기준 변경 권한 부여 금지.

### Exceptions

채널 수집 실패, 요약 실패, 재로딩/재분석 재실패, 결과 저장 실패를 구분한다. 실패 기록도 보존한다.

### Constraints

전체 저장, 글별 3문장, 불명확 태그 표시, 실패 자료 유지, 글 단위 1회 복구·재실패 유지가 Confirmed다. 다음 단계는 State 이름·저장 원자성·API·UI 등 상세를 검토한다. 이 단계에서는 기능을 실제 구현하거나 외부 Connector를 실행하지 않았다.
